# API 延迟升高处理手册

## 适用场景

接口响应时间明显增加，但不一定出现 HTTP 500。
用户可能反馈请求很慢、页面加载时间变长或请求超时。

## 初步确认

1. 确认延迟开始升高的时间、受影响的接口和服务实例。
2. 查看请求量、错误率和 P95、P99 响应时间。
3. 判断是单个接口变慢，还是多个接口同时变慢。

## 排查应用服务

1. 检查应用实例的 CPU、内存和线程池使用情况。
2. 检查请求是否存在排队、线程池耗尽或连接池等待。
3. 根据请求 ID 查看日志，定位耗时较长的处理步骤。

## 排查下游依赖

1. 如果数据库调用耗时增加，检查慢查询、连接池等待和数据库连接情况。
2. 如果 Redis 调用耗时增加，检查 Redis 响应时间、超时日志和连接池情况。
3. 如果外部 API 调用耗时增加，检查下游响应时间和超时情况。

## 检查近期变更

1. 确认延迟升高前是否发生代码发布或配置修改。
2. 对比变更时间和延迟升高时间，记录可能相关的变更。
3. 仅凭时间接近不能确定变更就是故障原因，需要结合日志和指标判断。

## 证据不足时

如果无法确定耗时发生在哪个环节，应请求补充接口名称、
异常时间段、请求 ID、相关日志和监控指标，不直接断定故障原因。
